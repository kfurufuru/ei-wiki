# 制御セキュリティの現場チェック

## 30秒まとめ

制御セキュリティは新しい学科ではなく、**いまやっている作業に確認項目が1つ増える**だけです。
盤を開けたとき・ベンダーが来たとき・仕様書を書くときの7場面で見るものを決めておけば、
専門知識がなくても現場の実態は把握できます。**最も効くのは仕様書と受入検査**です。

---

## IT のやり方をそのまま持ち込めない理由

情報系（IT）と制御系（OT）では、守るものの優先順位が逆転します。

| | 優先順位 |
|---|---|
| 情報系（IT） | 機密性 → 完全性 → 可用性 |
| 制御系（OT） | **安全 → 可用性 → 完全性 → 機密性** |

情報系は「怪しければ止める」が正解です。制御系は止めると人が危険にさらされるか、
設備が壊れるか、生産が止まります。

!!! warning "「パッチを当てろ」「ウイルス対策を入れろ」が通らない理由"
    - 適用するとベンダーの動作保証の対象外になる
    - 検証できる環境がない（本番機しかない）
    - 定修まで止められない
    - 対応 OS がサポート切れで、そもそも適用できるものが無い

    制御側の担当者の役割は、情報系のポリシーを現場に押し込むことではありません。
    **止められない前提で何ができるかに翻訳すること**です。

## 作業別チェック（7場面）

日常業務のついでに見るものだけを並べています。時間を取って調査する必要はありません。

### 1. 盤を開けたとき

| 見るもの | なぜ |
|---|---|
| 空きLANポートに何か刺さっていないか | 無断接続の入口になる |
| 用途不明のUSBメモリ・LANケーブル | 作業時の置き忘れが常態化していることがある |
| 後付けの無線AP・モバイルルータ・変換器 | **最も危険。誰がいつ付けたか分からない通信機器** |
| 盤の施錠状態 | 物理的に触れれば大半の対策は迂回できる |

!!! danger "見つけても、その場で抜かない"
    通信機器やケーブルが**現に制御に使われている**可能性があります。
    抜いた瞬間に設備が停止・誤動作する恐れがあるため、**写真を撮って記録し、
    設備担当・保全・ベンダーに用途を確認してから**処置を決めてください。
    「不審だから外す」は制御系では事故になります。

### 2. HMI・エンジニアリングPCの前に立ったとき

- OS の版数と、メーカーのサポート期限
- ログインしっぱなしになっていないか（離席時の画面ロック）
- パスワードの貼り紙・共有アカウントの有無
- USBポートの使われ方（常用されていないか）
- ウイルス対策ソフトの有無と、**ベンダーが許可しているかどうか**

### 3. ベンダー・協力会社が作業に来たとき

**7場面のうち、実務上これが一番効きます。**
実際のインシデントの侵入口はここが多いためです。作業報告書に次の3行を足すだけで足ります。

- 持込PCを使ったか（機種・持込者）
- USBメモリを使ったか
- 社外からのリモート接続をしたか

### 4. リモート保守回線を意識したとき

- 常時つながっているのか、必要時だけ開けるのか
- 誰が開閉を判断し、誰が実際に操作するのか
- 常時接続なら、**なぜ常時である必要があるのか**を一度だけ確認する

### 5. 仕様書を書くとき・メーカー選定のとき

**推進担当としてのレバレッジが最も大きい場面です。**
既設は簡単には直せませんが、これから入るものは決められます。仕様書に次の4行を入れます。

- OS・ファームウェアのサポート期限（納入時点で残り何年か）
- 初期パスワードの変更可否、アカウントを個人別に分けられるか
- 操作・変更のログを取得できるか、取り出せるか
- リモート接続の方式と、こちら側で遮断できる手段があるか

詳細は [仕様書の書き方](../04-sekkei/spec-writing.md)・[メーカー選定](../04-sekkei/vendor-selection.md) を参照してください。

### 6. 異常が起きたとき

制御系の事案は、初期には「原因不明の誤動作」として処理されがちです。
**「故障」と結論づける前に、1回だけ**次を確認します。

- いつから起きているか
- 同じタイミングで他にも異常が出ていないか
- 直前に誰かが触っていないか（工事・保守・設定変更）

切り分けの詳細は [PLC/DCSトラブル](../06-trouble/plc-dcs.md) を参照してください。

### 7. 図面・系統図を見るとき

制御系が情報系LAN・インターネット・無線とどこでつながっているかを確認します。
単線結線図ではなく**ネットワーク構成図**です。

!!! note "「無い」と分かること自体が成果です"
    制御系のネットワーク構成図が整備されていない現場は珍しくありません。
    無いことが分かれば、それが最初に作るべき成果物になります。

## 見つけたことをどう扱うか

1. **その場で処置しない**（前述のとおり停止・誤動作のリスクがある）
2. 写真と場所を記録する
3. 設備担当・ベンダーに用途を確認する
4. 用途が確認できないものだけを、正式な変更管理（MOC）に乗せて処置する

異常時の報告経路そのものは [電気事故対応と報告](../09-hoantokei/jiko-taiou.md) に従います。
**誰が設備停止を判断するのか**が決まっていない場合、それは制御セキュリティ以前の課題です。
