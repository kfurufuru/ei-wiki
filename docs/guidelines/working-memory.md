# 作業記憶の負荷を減らす — 困りごとと立場から引く実践集

**対象読者**: :material-account-hard-hat: 電気担当 / 保全担当 / 製造担当 / 管理職 / 新人 / 協力会社

---

## 30秒まとめ

> 作業中に頭の中で同時に保てる量（作業記憶）は少なく、訓練で仕事全般に効くほど増やせるという確かな裏付けはありません。だから**頭に載せる量そのものを減らす仕組み**で守ります。まず [困りごとから選ぶ](#situations) で、いま困っている場面の対策を1つ選んでください。安全の手順と重なる項目は [安全手順との関係](#safety) が境目を決めています。対策は入れて終わりにせず、[効果を確かめます](#review)。

!!! info "このページの位置づけ"
    心理学の知見と現場の慣行をもとにした**考え方と工夫の例**です。作業標準・作業許可・安全の手順ではありません。**社内の規程・作業標準・法令の定めが常に優先**します。判定の数値（許容値・濃度・期限など）はこのページに書きません。

## このページの使い方

1. [困りごとから選ぶ](#situations) で、いま困っている場面を1つ選びます
2. その場面の「対策・使う時点・効いたかの確かめ方」を読みます

## なぜ効くのか

作業記憶（ワーキングメモリ）は、作業の途中で情報を一時的に保ち、操作する頭の働きです。

- **容量が小さい**: 同時に保てるのは、意味のまとまりで数えて数個程度とされます。決まった1つの数ではなく、人や課題によって幅があります
- **増やしにくい**: 記憶の訓練で伸びるのは訓練に近い課題が中心で、仕事全般に効くという確かな裏付けはありません
- **知識のまとまりで扱える量が変わる**: ベテランは知識を大きなまとまりとして持っているので、同じ指示を少ない負荷で扱えます。新人とベテランの差には、ほかの要因（経験した場面の数・手の慣れなど）も関わります
- **状態で落ちる**: 疲労・睡眠不足（夜勤明けなど）・焦り・割り込みで、使える量はさらに減るとされます

各主張の典拠は [根拠](#evidence) に対応表があります。

## 困りごとから選ぶ {#situations}

| 記号 | 困りごと | 起きていること |
|---|---|---|
| [A](#forget) | 案件・依頼・期限を忘れる | 新しい仕事に押し出されて抜ける |
| [B](#interrupt) | 中断した後、どこまでやったか分からない | 途中の状態を頭に置いたまま離れる |
| [C](#mixup) | 似た機器・番号・項目を取り違える | 見分ける手がかりが少なく、思い込みで判定する |
| [D](#restore) | 外した物・変えた設定が元に戻ったか分からない | 変更を覚えておく前提で作業している |
| [E](#handover) | 指示・引継ぎ・依頼で情報が抜ける | 受け取る側が断片で抱える |
| [F](#overload) | 抱える案件・判断・割り込みが多すぎる | 同時に進める数が容量を超えている |
| [G](#abnormal) | 異常時に頭が埋まる | 対応と記録を同じ人が抱える |

### A. 案件・依頼・期限を忘れる {#forget}

- **対策**: 気がかり・案件・依頼を**1つの台帳か一覧**に集めます（状態・次の一手・期限・担当）。聞いたことと決まったことは、その場で書きます
- **使う時点**: 依頼を受けたその場。週に1回、全件を見直して次の一手を決めます
- **効いたかの確かめ方**: 期限を過ぎた件数。台帳に無かった依頼が後から見つかった件数

### B. 中断した後、どこまでやったか分からない {#interrupt}

- **対策**: 離れる前に**「どこまで済んだか・次に何をするか・戻すべきものは何か」**を1行書きます。再開するときは、そのメモを**現物と照らし合わせてから**続けます
- **使う時点**: 呼ばれて離れる前、休憩・交代の前。再開の直前
- **効いたかの確かめ方**: 再開後にやり直した件数。再開時の確認漏れによるヒヤリハットの件数

### C. 似た機器・番号・項目を取り違える {#mixup}

- **対策**: 機器・盤・弁・配線の**識別表示**を整えます。操作や判定の直前に、機器番号を**指差呼称**で確かめます。確認項目は**チェックリスト**にし、判定基準は表で手元に置きます（表には出典と改訂日を書き、正典が変わったら差し替えます）。重要な箇所は、別の人が**独立して**照らし合わせます
- **使う時点**: 操作・測定・判定の直前
- **効いたかの確かめ方**: 取り違えのヒヤリハットの件数。独立した照合で見つかった食い違いの件数

!!! warning "独立した照合とは"
    確認する人が、元の情報（図面・台帳・指示書）を自分で読み上げて照らし合わせることです。2人が同じ紙を一緒に見て「確認した」ことにすると、同じ思い込みのまま2人とも見落とします。

### D. 外した物・変えた設定が元に戻ったか分からない {#restore}

- **対策**: **変更前の状態・暫定の変更・復旧後の状態**を1枚の照合表に書きます。外した線・掛けたジャンパ・強制・設定の変更を、変えた時点で書き、復旧したら1件ずつ消し込みます。引き渡す前に、変更前の状態と復旧後の状態を突き合わせます
- **使う時点**: 変えた時点。引き渡す前（暫定の状態を残したまま引き渡しません）
- **効いたかの確かめ方**: 引き渡した後に暫定の状態が見つかった件数

### E. 指示・引継ぎ・依頼で情報が抜ける {#handover}

- **対策**: 指示は**復唱**し、重要なものは書面で補います。依頼は「何を・いつまでに・どの形で」を書きます。引継ぎは**様式**で行い、受ける側が要点を復唱します
- **使う時点**: 指示・依頼・引継ぎのその場
- **効いたかの確かめ方**: 受けた後に問い直した回数。引継ぎの抜けによるヒヤリハットの件数

### F. 抱える案件・判断・割り込みが多すぎる {#overload}

- **対策**: 同時に進める案件の数を絞り、大きな仕事は「次の具体的な一手」まで分けます。通知を切り、メールやチャットは時間を決めてまとめて処理します。重い判断や重要な操作は頭が冴えている時間帯に回します。分野の知識を体系的に積むと、同じ判断が少ない負荷でできるようになります
- **使う時点**: 週の計画を立てるとき。割り込みが重なったとき
- **効いたかの確かめ方**: 1人あたりの同時進行の案件数。作業中の割り込みの回数

### G. 異常時に頭が埋まる {#abnormal}

- **対策**: **対応する人と記録する人を分け**、「いつ・何が起きて・何をしたか」を時系列で書きます。対応している人は頭が埋まり、時刻や操作の順序を覚えていられないためです。よく起きる異常は、異常ごとに初動のカードを作っておきます（初動の順序は [トラブル初動対応フロー](trouble-first-response.md) が正典です）
- **使う時点**: 異常に気づいたとき
- **効いたかの確かめ方**: 復旧後の記録で、時刻や操作が抜けていた件数

## 安全手順との関係 {#safety}

このページの工夫は、安全の手順を**置き換えません**。次の4点は、このページの項目と正式な手順との境目です。

!!! danger "メモ・写真・1枚の指示書は正式な文書の代わりにしない"
    個人のメモ・写真・1枚にまとめた作業指示書は、**理解と記録を助ける補助**です。正式な作業標準・図面・作業許可（PTW）の代わりに使いません。補助と正式な文書が食い違ったら、正式な文書に従います。写真は、構内の撮影許可と防爆区域の持込みの制限に従って撮ります。

### 無電圧の確認

- 無電圧を前提とする作業では、作業を始める前に**対象の電路を特定**し、遮断と誤通電の防止（施錠・札）を行います。そのうえで、社内の停電作業の標準に従って**無電圧を確認**します。残留電荷などの残ったエネルギーも確認の対象です
- 高圧・特別高圧の電路では、所定の**検電と短絡接地**を行います
- 作業の範囲や条件が変わったら、**確認をやり直します**
- 札や「切ったはず」という記憶は、無電圧の根拠になりません
- 通電したまま信号を測る作業は、前提が違います。その作業の手順と社内の定めに従います

正典: [停電作業](../05-hozen/outage-work.md) / [LOTO](../10-safety/lockout-tagout.md)

### KY の重点

- リスクアセスメントで挙げた危険には、**それぞれ必要な対策を取ります**
- 作業前の KY では、そのうえで、当日特に注意を集める**重点を少数に絞って**全員で共有します
- **重点から外れた危険の対策も省きません。** 重点は注意の向け先であり、対策の範囲ではありません
- 作業許可と KY は、リスクアセスメントの代わりになりません

正典: [リスクアセスメント](../10-safety/risk-assessment.md) / [作業許可制度](../10-safety/ptw.md)

### バイパス・強制・ジャンパ

インターロックのバイパス、強制 ON/OFF、ジャンパは、記録するだけでは管理になりません。次の流れを社内の手続きで行います。

1. **理由と影響範囲を確かめます**（どの保護・インターロックが効かなくなるか）
2. **リスクを評価し、代替措置を決め、承認を得ます**（監視の強化・運転の制限など）
3. **台帳に状態・責任者・解除の期限を書き**、画面と現場の札で表示し、関係者と当直の引継ぎで共有します。運転部門と電計は同じ1つの台帳を使います
4. **解除したら機能が戻ったことを確かめ**、別の人が独立して確認してから台帳を閉じます

SIS のバイパスは、通常の制御の強制操作より影響が大きいため、対象の機能ごとに正式な管理手順に従います。

正典: [機能安全（SIS/SIL）](../03-keiso/sis-sil.md) の「バイパス（オーバーライド）管理」

### 重要な操作の最中の声かけ

重要な操作の最中は、用件のための声かけをしません。ただし**危険や誤操作に気づいたときは、すぐ声を出して止めます**。この例外は、ルールを作るときに必ず併せて決めます。

## 立場別の例 {#roles}

各項目の頭の記号は、[困りごと](#situations) の A〜G に対応します。困りごとの対策（全員共通）に加えて、その立場に固有の例だけを載せています。

### 現場で手を動かす立場

=== "電計"

    - **D**: ジャンパ・強制・設定の変更は、**変更前・暫定・復旧後**の3つを照合表に書き、引き渡す前に突き合わせます。暫定の設定を残したまま設備を引き渡しません
    - **D**: 端子を外す前に線番と端子番号を記録し、外した線には札を付けます。写真は記録の補助です
    - **C**: 停電・隔離の範囲を単線結線図やループ図に書き込み、作業者全員で同じ図を見ます。隔離の手順そのものは正典に従います
    - **C**: ループチェックや校正は、入力値・期待出力・許容差の欄がある記録用紙を事前に作り、その場で書き込みます
    - **F**: よく起きる故障は切り分けフローにしておきます

    無電圧の確認とバイパスは [安全手順との関係](#safety) を読みます。

    関連: [計装ループチェック](loop-check.md) / [保護リレー試験](protective-relay-test.md) / [計器の校正](../05-hozen/calibration.md) / [停電作業](../05-hozen/outage-work.md)

=== "機械"

    - **C**: 縁切り（隔離）は、閉める弁の番号・盲板の位置・ドレンとパージの手順を縁切りリストに書きます。電気側の隔離は電計に依頼します
    - **C**: 開放前の残圧・残液・温度・ガスの確認は、チェックシートで1項目ずつ行います。判定の値は社内の基準に従います
    - **D**: 分解した部品には合いマークと番号札を付け、外した順にトレイへ並べます。組立は並び順で戻します
    - **D**: 締付トルクと締付順序は手順書で確かめ、締め終えたボルトに印を付けます
    - **E**: 試運転での回転方向やインターロックの確認は、電計と役割分担表を作って進めます

    関連: [LOTO](../10-safety/lockout-tagout.md) / [データ活用・予兆保全](../05-hozen/predictive-maintenance.md) / [予備品管理](../05-hozen/spare-parts.md)

=== "運転部門"

    - **C**: スタートアップ・シャットダウン・切替は、操作手順書を読み上げながら1ステップずつ進め、済んだ所にチェックを入れます。めったにやらない操作ほど手順書を使います
    - **C**: 操作する前に、機器番号を画面と現場の両方で指差呼称します
    - **D**: バイパスや強制操作は電計と同じ1つの台帳で管理し、引継ぎのたびに残っているものを確認します
    - **E**: 縁切りの引渡しと復旧の受取りは、縁切りリストに沿って1つずつ確認し、署名で受け渡します
    - **G**: よく起きる異常は、異常ごとに初動のカードにします。警報が多すぎて大事な警報が埋もれるときは、設備部門と協力して整理します

    関連: [トラブル初動対応フロー](trouble-first-response.md) / [作業許可証（PTW）発行手順](work-permit.md) / [作業許可制度](../10-safety/ptw.md)

=== "協力会社"

    **作業者・職長**

    - **E**: 作業許可の条件（時間・範囲・ガス測定・監視人など）は、作業前に班全員で読み上げます
    - **C**: その日の作業範囲は、発注者と現地で指差して確認し、札やテープで区画します
    - **D**: 隔離・施錠は、一人ひとりが自分の鍵と名札を掛けます
    - **F**: 作業の変更や範囲外の作業が出てきたら、自分で判断せず手を止めて発注者に連絡します

    **発注側**

    - **E**: 作業許可・作業標準に加えて、要点（範囲・止めてある設備・危険・連絡先）を1枚にして渡します。1枚は正式な文書の代わりではありません
    - **C**: 機器番号・弁の開閉表示・配管の識別表示を整えます。表示が正しければ、協力会社が覚えなくて済みます

    関連: [作業許可制度](../10-safety/ptw.md) / [特別教育・資格一覧](../10-safety/special-education.md) / [LOTO](../10-safety/lockout-tagout.md)

=== "新人"

    - **A**: 現場手帳に、教わったことを自分の言葉で書き直します。手帳は理解の補助で、手順書の代わりにはしません
    - **F**: 最初に設備の全体像を1枚の図でつかみ、後から覚える知識をその図に結びつけます
    - **F**: 指示が重なったら、どれを先にやるか上司に聞きます。自分だけで抱えません
    - **G**: 安全に関わる場面で迷ったら、**止める・呼ぶ・待つ**
    - **C**: 手順書・チェックリストは毎回使います。慣れてきた頃が一番危険です

    関連: [読み方ガイド](../getting-started.md) / [ガイドライン一覧](index.md)

### 計画・管理・支援の立場

=== "計画"

    - **A**: 法定点検・検査の期限を一覧にし、準備期間から逆算した日に通知が来るようにします
    - **A**: 予算は「計画額・発注済み額・残り」を表で持ちます。頭の中で足し引きしません
    - **A**: 発注から支払までの段階（見積依頼 → 査定 → 発注 → 工事 → 検収 → 支払）を、台帳の状態として持たせます
    - **F**: 優先順位の基準を表にし（例: 法令・安全 → 生産への影響 → 費用）、決めたことは決定・理由・採用しなかった案を記録します
    - **F**: 工程表では、遅れると全体が遅れる作業の並び（クリティカルパス）と、納期の長い資材の発注期限を見えるようにします

    関連: [保全体系](../05-hozen/maintenance-system.md) / [定期点検](../05-hozen/periodic-inspection.md) / [工事・検収フロー](../03-koji-kenshu/flow-overview.md)

=== "安全"

    - **C**: 作業許可の審査は、作業の種類ごとのチェックリストで行います
    - **F**: 当日の危険作業と作業許可をエリア図に書き込み、同時に進む作業を図で見ます
    - **A**: パトロールの指摘は、是正台帳（指摘・担当・期限・是正の確認日）で管理します
    - **C**: 「覚えさせる」より「見えるようにする」: 配管の識別色、弁の開閉表示、危険区域の区画。手順書は1ステップ1動作で書きます
    - **C**: KY と、重要な操作の最中の声かけのルールは、[安全手順との関係](#safety) の扱いで決めます

    関連: [作業許可制度](../10-safety/ptw.md) / [リスクアセスメント](../10-safety/risk-assessment.md) / [ヒヤリハット](../10-safety/near-miss.md)

=== "品質保証"

    - **C**: 検査や立会いは、検査項目・判定基準・測定値の欄を持つ記録表を事前に作り、その場で書き込みます
    - **A**: 計測器は校正期限の台帳とラベルで管理し、期限切れの計器には使用禁止の表示をします
    - **A**: 不適合は様式で登録し、是正の期限と効果の確認日を台帳で管理します
    - **C**: 文書は版を管理し、最新版が一目で分かるようにします
    - **F**: 合否が微妙なものは1人で抱えず判定の場を設け、基準・根拠・判断した人を記録します

    関連: [計器の校正](../05-hozen/calibration.md) / [工事完了後の受入実務](../03-keiso/koji-kanryo.md)

=== "事務"

    - **A**: 処理待ちの書類・依頼は1か所（トレイか一覧表）に集め、受付日・依頼者・期限・状態を書きます
    - **A**: 月次・年次の締め日を年間カレンダーに書き、前もって通知が来るようにします
    - **E**: よく来る依頼は依頼様式を作り、依頼する側に必要事項を書いてもらいます
    - **C**: 金額や数量の入力は、元の書類と並べて照らし合わせます。大きな金額は別の人が独立して確認します
    - **F**: 入力などの集中する仕事と、問い合わせ対応の時間帯を分けます

    関連: [工事・検収フロー](../03-koji-kenshu/flow-overview.md)（工事の企画から検収・引継ぎまでの全体像）

=== "管理職"

    - **F**: 優先順位が衝突したときの順序と、差し替えを決める人を前もって決めます（例: 安全上の緊急 → 設備停止に直結する案件 → 計画工事）。差し替えたら、影響を受ける人に伝えます
    - **F**: 割り込みの元を減らします。不要な会議・重複した報告・過剰な承認を棚卸しし、やめるものを決めます
    - **F**: 人ごとの同時進行の案件数を見えるようにし、突発の依頼の窓口を一本化します
    - **F**: 決裁の基準と権限を明文化し、部下に任せる判断を決めます
    - **E**: 報告の型を決めます（結論・理由・選択肢・推奨案・期限）
    - 対策を入れたときの指標と見直す日を決めます（[導入と効果の確かめ方](#review)）。安全や品質に関わる作業は急がせません

    関連: [保全体系](../05-hozen/maintenance-system.md) / [ヒヤリハット](../10-safety/near-miss.md)

---

## 導入と効果の確かめ方 {#review}

1. 職場で困りごとを1つ選び、対策を1つ入れます。一度に増やしません
2. 入れる前に、**指標**（各困りごとの「効いたかの確かめ方」）と**見直す日**を決めます。決めるのは職場の管理職で、記録に残します
3. 見直す日に、指標と、使った人が迷った点を集めます。続ける・直す・やめるを決めます
4. 項目を増やす前に、使われていない項目を減らします

## やってはいけないこと

!!! danger "頭に抱えたまま進めない"
    - 途中の値・番号・手順を頭に覚えたまま次へ進む
    - 「前と同じ」「いつもどおり」を記憶だけで判断する
    - 口頭だけの指示や引継ぎで済ませる
    - 2人が同じ紙を一緒に見て、二重確認したことにする
    - メモ・写真・1枚の指示書を、作業標準や作業許可の代わりにする
    - 重要な操作の最中に、用件のための声かけや割り込みをする（危険や誤操作に気づいたときは、すぐ声を出して止めます）

### 研究で支持される一般的な知見
