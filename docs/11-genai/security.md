# 注意事項・情報セキュリティ

## 30秒まとめ

生成AIに図面・個人情報・未公開の技術情報を入力してはいけない。ツールごとに学習利用の可否が異なるため、社内ポリシーで許可されたツール・用途だけを使う。AI出力の検証は利用者の義務。

---

> 生成AIは「便利なツール」だが、**使い方を間違えると情報漏洩・技術的ミスのリスクがある**。
> このページは全員が読んでから使い始めること。

---

## 絶対に入力してはいけない情報

以下の情報は、M365 Copilot（会社契約）以外のサービスには**絶対に入力しない**。

| カテゴリ | 具体例 |
|---------|--------|
| 社外秘の設備情報 | プロセス詳細条件・配管系統図・P&ID・制御ロジック |
| 投資・財務情報 | 未公表の設備投資計画・調達価格・コスト情報 |
| 取引先・顧客情報 | メーカー担当者名・取引条件・価格交渉の内容 |
| 個人情報 | 社員の氏名・社員番号・連絡先・評価情報 |
| 事故・インシデント情報 | 未報告の事故・ヒヤリハット・詳細なトラブル経緯 |
| 知的財産 | 独自技術・特許出願前のアイデア・社内ノウハウ |

!!! danger "「概要しか書いていない」は言い訳にならない"
    「具体的な数値は書いていない」という判断は危険。設備名・工場名・工程名の組み合わせだけでも、競合他社や悪意ある第三者には有用な情報になる可能性がある。判断に迷ったら入力しない。

## 情報漏洩の実例（2023年）

!!! example "Samsung（海外電子機器メーカー）の事例"
    2023年3月、海外の電子機器メーカーで社内機密を生成AIに入力してしまう事案が、利用許可からわずか20日ほどの間に立て続けに3件発生し、機密漏洩事案として報道された。

    | 件 | 何をしたか | 何が社外サーバーへ渡ったか |
    |----|-----------|--------------|
    | ❶ | 社内機密のソースコードを生成AIに貼り付けて修正を依頼（2件） | ソースコード |
    | ❷ | 社内会議の録音データを音声認識で文字化し、そのまま生成AIに入力して議事録を作成（1件） | 会議の内容 |

    **なぜ問題になったか：** 使用したサービスが「入力データを学習に使う可能性がある」一般向けサービスであり、入力した時点で機密が社外サーバーへ送信され、会社の管理下から出てしまうため。ハッキングではなく、**社員自身の入力操作**が原因だった。

    この事例の後、多くの企業が社員への生成AI利用ガイドラインを整備・強化した。

!!! info "M365 Copilotが安全な理由"
    会社契約のM365 Copilotは、プロンプト・応答・Microsoft Graph経由でアクセスされるデータが**基盤LLMのトレーニングに使用されない**（Microsoftの公式ドキュメントに明記）。また、データは会社のMicrosoft 365テナントのサービス境界内で管理され、アクセス制御はMicrosoft Entra ID（旧称 Azure Active Directory）のアクセス許可に従うため、テナント外の第三者からは参照できない。ただし、会社のIT管理者に確認してから使用すること。

## AI出力の検証義務

**「AIが言った」は根拠にならない。**

AI出力を業務に使う場合は、**エンジニアが内容の正確性に責任を持つ**。

### 検証が必須の項目

| 出力の種類 | なぜ検証が必要か | 確認方法 |
|-----------|--------------|---------|
| 規格値・法定値 | ハルシネーションで架空の数値が出ることがある | 一次資料（JIS・IEC・法令本文）で確認 |
| 計算結果 | 複雑な計算は誤りが出やすい | 電卓・Excelで独立して計算し直す |
| 設備仕様の記述 | 古いデータや誤情報が混ざることがある | メーカーデータシートで確認 |
| 法令の引用 | 条番号・条文が間違っていることがある | e-Gov法令検索等で一次情報確認 |
| トラブル解析の原因候補 | AIの推論は可能性の列挙にすぎない | 現場の実測・履歴と照合して判断 |

### 検証の実践

```
NGな使い方：
- AIが「IEC 61511-1の3.4条に従い...」と書いたのをそのまま稟議書に貼る

OKな使い方：
- AIのドラフトを参考に、実際にIEC 61511-1を参照して条番号・内容を確認した上で記載する
```

## 著作権・知的財産権のリスク

生成AIが作ったコンテンツを使う際、**他者の著作権・商標権などを侵害するリスク**がある。

### 特に注意が必要な場面

| リスク | 具体例 | 対策 |
|--------|--------|------|
| 著作物に類似した画像の生成 | 既存アニメキャラクターに似た絵を生成し社外に公表する | 生成物が既存のものに似ていないか確認。商用利用は特に慎重に |
| 著名人の画像・発言の無断利用 | 実在する人物の顔・声を生成してSNSに投稿する | 実在の人物を模倣した生成はしない |
| 商標・ロゴに類似したデザインの使用 | 競合他社のロゴに似たデザインをそのまま資料に使う | 商標登録の確認が必要 |

!!! warning "業務資料での画像生成利用"
    社内プレゼン・提案資料で画像生成AIを使う場合でも、著作権上グレーなコンテンツは避ける。
    特に「〇〇に似た絵」「〇〇社のデザインを参考にした」という指示は出さない。

### 入力側のリスク（学習データの問題）

自分のプロンプトに他者の著作物（書籍の文章・設計図・仕様書等）を**そのまま貼り付けて入力するのも注意が必要**。生成AIへの入力は「利用」に該当するケースがある。

## 生成AI利用に関する会社ポリシー

生成AIの業務利用については、会社全体のポリシーが適用される場合がある。

**利用前に確認すること：**

- [ ] 自社のAI・ITツール利用規程を確認する
- [ ] M365 Copilotの利用はIT管理者に可否を確認する
- [ ] ChatGPT等の外部サービスを業務利用する際は部門長に確認する
- [ ] 社内情報を扱う場合はセキュリティ担当者に相談する

!!! note "個人の業務改善ツールとして使う場合"
    社外秘情報を含まない一般的な文書作成・翻訳・技術調査であれば、個人の業務改善ツールとして常識の範囲で活用できる。ただし「社外には出てはいけない情報」の線引きは常に意識する。

## まとめ：判断フローチャート

```
入力しようとしている情報は何か？

├── 一般的な技術情報・公開情報
│   └── どのツールでも入力OK
│
├── 社内の設備情報・業務情報（社外秘含まない）
│   ├── M365 Copilot（会社契約）→ 入力OK
│   └── ChatGPT / Claude.ai → 慎重に。社名・設備名の組み合わせに注意
│
└── 社外秘・個人情報・投資情報・未公表情報
    ├── M365 Copilot（会社契約）→ 入力可（ただし会社ポリシー確認）
    └── ChatGPT / Claude.ai → 入力禁止
```

### 本ページが正典の範囲

本ページは「生成AI利用時の**情報の取り扱いルール**（入力禁止情報・ツール別判断・出力検証義務）」の正典です。各ツールの機能・使い方は [生成AIの基本](basics.md)・[M365 Copilot活用](m365-copilot.md) が正典で、本ページでは扱いません。

### 一次照合済み（公式一次資料 照合）

| 資料 | 確認した内容 |
|---|---|
| Microsoft Learn「Microsoft 365 Copilot のデータ、プライバシー、セキュリティ」（2026-07-09版） | 「Microsoft Graph 経由でアクセスされるプロンプト、応答、データは…基礎 LLM のトレーニングには使用されません」の逐語確認。データはテナントの契約上のコミットメントに沿って保存・暗号化されること、アクセス制御が Microsoft Entra 承認によることも同資料で確認 |

- Samsung の2023年3月の事案（ソースコード入力2件＋会議内容入力1件、利用許可から約20日間で発生、事後に利用制限を強化）は、PC Watch ほか複数の報道で一致を確認した。当事会社の公式発表原文は未入手

### 是正の記録（2026-08-05）

- 「厚生労働省『AI・IT化に伴う労働者の情報セキュリティ』」という出典を**削除** → 同名の厚労省文書の存在が確認できなかった（存在しない出典の疑い）。「未照合の出典を掲げない」方針により除去
- 「経済産業省『AI事業者ガイドライン（2024年版）』」→「**総務省・経済産業省**『AI事業者ガイドライン』」 → 単独省庁への誤帰属を是正。版も固定年表記をやめ「随時改訂あり・最新版を確認」に変更
- 「会社のAzure Active Directory内でデータが管理されるため、社外には出ない」→「データはMicrosoft 365**テナントのサービス境界内**で管理され、アクセス制御はMicrosoft Entra ID（旧称 Azure Active Directory）による」 → Azure ADはID・アクセス管理基盤でありデータの格納場所ではない誤りと、旧称を現行名として書いていた点を是正
- 「入力データがトレーニングに使用されない（エンタープライズ契約の条項）」→ Microsoft公式ドキュメントの記載として根拠を明示
- Samsung事例の「なぜ漏洩したか」→「なぜ問題になったか」 → 第三者への流出が確認された事案ではなく「機密が社外サーバーへ送信された（会社の管理下から出た）」事案であることを明確化

### 原本未照合（honest-hold）

- OpenAI・Anthropic の利用規約・プライバシーポリシー原文は未照合。「入力データを学習に使う可能性がある」は個人向けサービスの一般的な扱いとしての記述で、**法人契約（ChatGPT Enterprise / Claude for Work 等）やオプトアウト設定では扱いが異なる**
- 生成AIへの入力が著作権法上の「利用」に該当するか否かの法的判断は、本Wikiでは条文・判例を照合していない。「注意が必要」の水準に留める

### 限界の明示

- 本ページは**自社のAI利用規程・セキュリティポリシーの代替ではない**。ツールの利用可否・入力可否の最終判断は、必ず自社のIT部門・セキュリティ担当者の判断による
- 各サービスのデータの取り扱いは**契約形態と設定で変わり、頻繁に改定される**。本ページの表を根拠に「このツールなら入力してよい」と確定しないこと
