# 記事鮮度監査ダッシュボード

本Wikiでは各記事のフロントマターに `last_verified: YYYY-MM-DD` を記録し、最終確認日からの経過日数で **EXPIRED / DUE_SOON / OK** の3バケットに分類して鮮度を管理します。**バケット境界はセクションごとに違います**（2026-09-19 に一律 365 日から区分制へ変更）。月初に GitHub Actions で自動スキャンし、EXPIRED が1件でも残っていれば CI が失敗するように連動させています。

## 再検証の間隔は分野で変えています

| 対象 | 間隔 | 理由 |
|---|---|---|
| `11-genai/`（生成AI） | **180 日** | 製品名・料金・機能が半年で変わる。2026-08 に旧ドメイン・月額料金など 6 件を実際に是正した |
| それ以外 | **730 日** | 法令・規格に錨を持つページが大半で、1 年では条番号が動かない（2026-07 → 09 の再照合で異同ゼロ） |

DUE_SOON は満了の **60 日前**から点きます。

!!! warning "730 日が許されるのは、カレンダーが唯一の見張りではないからです"
    間隔を延ばした代わりに、次の 3 本が常時効いています。**どれかを外すなら間隔も戻す必要があります。**

    - `scripts/check_law_revisions.py` — 引用している法令 17 件の改正を e-Gov 法令 API で直接検出する**イベント起動**の見張り。改正があれば、その法令を引用する全ページを名指しで挙げて CI を落とす
    - `scripts/check_content_rules.py` — 既知の誤り値を `FORBIDDEN` で止め、正典値を `canary` で守る
    - `.github/pull_request_template.md` — 新しく書いた数値に一次照合表（出典 URL と照合日）を要求する

### なぜ一律 365 日をやめたか

両方向に間違っていたためです。生成AI のページは 365 日では遅すぎ、法令アンカーのページは速すぎて空振りしていました。加えて **136 ページを 365 日で 1 周するには週 2.6 ページ**が要り、運用している**週 2 ページでは 1 周に 476 日**かかって構造的に追いつきませんでした。区分制にすると必要ペースが **1.60 ページ/週**に下がり、週 2 ページで定常の EXPIRED がゼロになることをシミュレーションで確認しています（毎週いちばん超過率の高い 2 件を消化する前提・260 週）。

自動スキャンは毎月1日（UTC）に GitHub Actions（`check-stale.yml`）で実行されます。最新の結果が必要なときは下記コマンドでローカル実行してください。

## ローカル実行方法

リポジトリルートから以下を実行すると、Markdown 表形式で鮮度レポートが標準出力に出ます。

```bash
# 全件一覧
python scripts/check_last_verified.py

# CI モード（EXPIRED があれば exit 1）
python scripts/check_last_verified.py --ci

# 基準日を指定して試算（例: 半年後の状態）
python scripts/check_last_verified.py --today 2026-11-19

# 次に検証すべき順に10件だけ出す（古い順 → 同じ古さなら被リンクの多い順）
python scripts/check_last_verified.py --queue 10
```

外部ライブラリ依存はなく、Python 3.11 標準ライブラリのみで動作します。

## 一括日付の「崖」に注意

同じ `last_verified` を持つ記事がまとまって存在すると、**ある日いっせいに EXPIRED 化**して一度に数十件の再確認を迫られます。既定レポートと `--queue` は、同一日付が10件以上あるとその旨を警告します。

日付だけを機械的に書き換えて回避してはいけません（実際に内容を確認していない記事の日付を進めると、鮮度管理そのものが嘘になります）。`--queue` で上位から少しずつ消化し、**実際に内容を確認した記事だけ**日付を更新してください。

!!! tip "更新ルール"
    - 記事を実質修正した際は、フロントマターの `last_verified` を必ず当日日付に更新する
    - 間隔（生成AI 180 日／その他 730 日）を超えた記事が残っていると CI（月初実行）が失敗する
    - DUE_SOON（満了 60 日前）に入ったら、次回編集機会に優先的に再確認する
    - 引用法令が改正されると、間隔に関係なく `check_law_revisions.py` が該当ページを名指しで挙げる

## 根拠

### 本ページの位置づけ — 索引であって正典ではない

記事の監査状況を一覧するページです。

判断に使う数値・基準・手順は**すべて各正典ページが持ち**、本ページは値を独自に定義しません。索引の値がずれると、読者は正典に到達する前に誤った物差しで判断してしまうため、**表中に数値や定義を書くときは必ず正典ページへのリンクを併記する**方針です。
