# Excel Copilot 実践ガイド

**対象読者**: :material-account-hard-hat: 電気担当 / :material-account: 計装担当

---

## 30秒まとめ

Excel の Copilot が「使えない」と感じる原因の大半は、Copilot 側ではなく**データの置き方とプロンプトの出し方**にあります。ファイルを OneDrive に置き、データをテーブルにし、「目的・使う列・出力の形」を毎回指定すれば、点検記録やトラブル記録の集計・分類はそのまま任せられます。

自由記述の故障記録を原因区分に分類する、といった今まで手作業だった仕事も、Copilot のチャットに列ごと渡せば一括で終わります。ただし出力は毎回わずかに揺れるため、**集計値は必ず検算し、確定した結果は元データと分けて固定する**のが作法です。

!!! note "COPILOT 関数は提供終了"
    セル内で AI を呼ぶ COPILOT 関数は、Microsoft 公式ページによると **2026 年 9 月 14 日をもって Excel から利用できなくなりました**（根拠節参照）。本ページの分類・抽出手順はすべて Copilot のチャット（作業ウィンドウ）経由で書いています。

!!! warning "先に読む"
    Copilot に渡してよい情報の範囲は [注意事項・情報セキュリティ](security.md) が正典です。会社契約の M365 Copilot でも、入力可否の最終判断は社内規程と IT 部門によります。本ページは「使い方」だけを扱います。

## 1. 最初の壁を先に潰す

Copilot が反応しない・的外れな答えを返すときは、まず次の 4 点を確認します。ここで止まっている人が非常に多く、Copilot の性能とは無関係です。

| 確認項目 | なぜ必要か | 対処 |
|---------|----------|------|
| ファイルが OneDrive か SharePoint にあり、自動保存が ON | 以前は必須条件でした。現行の公式ページは自動保存の有無にかかわらず動くとしていますが、動かないときの最初の確認点です。変更履歴が残る点でも会社の OneDrive 保存が安全です | 会社の OneDrive へ移し、自動保存を ON にする |
| データが「テーブル」になっている | Copilot はテーブルを単位に理解します。ただの範囲は正しく読めません | 範囲を選んで `Ctrl + T` |
| 1 行目に見出し、結合セルなし、空行なし、日付は日付型 | 見た目重視の報告書レイアウトでは列の意味を取り違えます | 生データのシートと見せるシートを分ける |
| 列名が短く具体的 | Copilot は列名を手がかりに解釈します | 「値」ではなく「停止時間_分」「原因区分」のように |

!!! tip "生データと見せる表は分ける"
    Copilot に読ませるのは生データのテーブルだけにします。上司向けの体裁を整えた表は、生データから数式やピボットで作る別シートに置きます。[予兆保全](../05-hozen/predictive-maintenance.md) の記録シートの列構成は、そのまま Copilot が読める形です。

## 2. 自由記述を構造化する（分類・抽出）

トラブル記録の「現象・処置」欄のような自由記述は、そのままでは集計できません。Copilot のチャットに列を指定して渡すと、区分を付けた新しい列として返してくれます。

```text
「原因メモ の列を読んで、電気/機械/操作ミス/その他 のどれかに分類し、
『原因区分』という新しい列に入れて。区分名だけ入れて、理由は書かないで」
```

| できること | 電気計装での例 |
|-----------|--------------|
| 自由記述の分類 | トラブル記録の文章を原因区分に自動分類する |
| 項目の抽出 | 日報の文から作業種別・対象設備種別を抜き出して別列にする |
| 要約 | 長い特記事項を 1 行に要約して一覧化する |
| 表記ゆれの統一 | 「圧力伝送器」「圧力TX」「PT」を 1 つの表記に揃える |

数百行でも一度の依頼で処理できます。行数が多いときは、まず 20 行ほどで試して区分の付き方を確認してから全体に広げます。

!!! warning "分類させるときの 2 つの作法"
    - **選択肢をプロンプト内で固定する。** 「分類して」だけでは毎回違う区分名が返り、集計できません。「電気/機械/操作ミス/その他 のどれか」「区分名だけ」と書きます。
    - **結果は元データと分けて固定する。** 分類結果は確率的で、同じ依頼でも次回は変わり得ます。返ってきた列を元データの列に上書きせず、確定したら別列として値のまま残し、再分類のときは新しい列に出します。

## 3. チャット側で効くプロンプトの型

「このデータを分析して」のような丸投げは弱い結果しか返しません。次の 3 点を毎回入れます。

1. **目的**: 何を判断したいか
2. **使う列**: どの列を見せるか
3. **出力の形**: 表かグラフか列追加か。値か数式か

```text
悪い例：
「点検データを分析して」

良い例：
「どの設備種別に保全工数を寄せるか決めたい。
設備種別、停止時間_分、発生月 の列を使って、
月別×設備種別の停止時間合計をピボットで出して」
```

### 「数式で入れて」と言う癖

列を追加させるとき、**「数式で入れて、値にしないで」**と付けます。値で返されると中身を検証できません。数式で返させれば、参照している列と計算の中身を見て正誤を判断できます。

### 電気計装業務での依頼例

点検記録（設備種別・点検日・測定値・判定）やトラブル記録が入ったテーブルを開いた状態で：

| 場面 | 依頼例 |
|------|-------|
| 傾向をつかむ | 「設備種別ごとの異常判定件数を月別に集計して」 |
| 抽出 | 「判定が『要注意』以上の行だけ抽出して、停止時間の多い順に並べて」 |
| 列を足す | 「前回測定値との変化率の列を数式で追加して」 |
| グラフ | 「絶縁抵抗の推移を設備種別ごとに折れ線で」 |
| 数式の解読 | セルを選んで「この数式を説明して」 |

### 段階的に深掘りする

一発で当てようとせず、「データの傾向を見せて」で全体像を出させ、気になった点を「〇〇の月別推移を折れ線で」と絞ります。

### 高度な分析

Copilot が Python in Excel でコードを書き、相関・予測・外れ値検出を行う機能があります。Python を書けなくても、結果とコードの両方が残るので、何をしたかを後から追えます（利用可否はライセンスと更新状態によります）。

## 4. 検算の作法

Copilot の答えを一度は自分で検算します。特に集計値です。

- **別の方法で同じ数を出す。** テーブルの SUBTOTAL や別のピボットで突き合わせる
- **件数を数える。** 元データの行数と、集計結果の合計件数が合うか
- **数式で返させたものは参照範囲を見る。** テーブル全体を参照しているか、途中で切れていないか

信頼できる範囲が分かってきたら、そこだけ検算を省きます。最初から省いてはいけません。検証の考え方は [注意事項・情報セキュリティ](security.md) の「AI出力の検証義務」が正典です。

## 5. 上達を速める練習法

- **自分の実データで毎日 10 分。** サンプルではなく、手元の点検記録やトラブル記録を使います。判断できる素材でないと「合っているか」が分からず、上達しません
- **効いたプロンプトを 1 シートに貯める。** ブックに「プロンプト帳」シートを作り、うまくいった文をそのまま貼ります。次から流用でき、書き方が定型化していきます
- **失敗も残す。** 「この言い方では列を取り違えた」という記録が、同僚に教えるときの教材になります

## 6. できないことを知っておく

| できないこと | 代わりに使うもの |
|------------|---------------|
| 開いているブックの外を見る | 別ファイルの結合は Power Query で先に済ませる |
| VBA マクロを書く | 公式に確認できていません。自動化は Office スクリプトか Power Automate を第一候補に |
| 機密・個人名を含むデータの無条件な処理 | [注意事項・情報セキュリティ](security.md) の判断フローに従う。個人名は記号化、設備は種別レベルまで |
